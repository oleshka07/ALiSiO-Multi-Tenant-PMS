# Верифікація хуків `.claude/` у свіжій сесії

Дата: 2026-08-27. Сесія: свіжий клон у віддаленому середовищі Claude Code
(не та сесія, що створювала хуки). Очікуваний результат обох тестів —
відмова PreToolUse-хука. Так і сталося: **обидва тести заблоковано**.

## (а) SessionStart-хук — вивід у контекст (дослівно)

```
── Стан репозиторію на старті сесії ─────────────────────────────────
Гілка: beta
Робоча копія чиста.

beta попереду main на 4 коміт(ів): зміни перевіряються на беті
й чекають merge у main. Це правильний напрямок потоку, не тривога.

── docs/ARCHITECTURE.md §8 — «Лишається» ────────────────────────────
**Лишається:**

- **SQLite у розробці.** `src/lib/db.ts` досі єдине джерело схеми, і
  `pg-schema.mjs` генерує Postgres-схему з **локальної** копії. Копія,
  старша за закомічену схему, дала б схему без нових колонок — тепер
  генератор відмовляється писати, якщо колонки зникають (`--allow-removals`
  для свідомого видалення). Порядок колонок при цьому може змінюватись від
  машини до машини; це косметика, позиційних `INSERT ... VALUES` у коді
  немає.
- **POST-и під навантаженням.** Прохід 08-08 по всіх 247 маршрутах закрив
  GET (170 маршрутів, 0 × 5xx). З 98 POST-ів 90 відсіклися на валідації,
  так і не дійшовши до SQL — тобто цей бік перевірений слабко.
- **Фаза 4** — тарифи й ліміти підписки, самореєстрація й онбординг
  (обидва потребують продуктового рішення власника).
- ~161 агрегатний запит, який статичний аудит позначає критичними:
  переважно звіти всередині вже проскоупленого модуля, але кожен треба
  переглянути. Починати з `finance/api/reports.handlers.ts` — там підсумки
  виду `SUM(amount) WHERE month = ?` без організації.
- `/api/checklists` падає на кожному виклику (читає неіснуючу таблицю
  `bookings`, правило зашите під «сауна»).
- **Логіка під будову F першого клієнта** — модалка розселення малює
  фізичний коридор F1–F17 (`RoomAllocationModal`; її кнопка зʼявляється
  лише там, де юніти `F\d+` реально існують). Правильний фікс — схема
  кімнат як налаштування обʼєкта. Excel-імпорт Booking.com (із перевагою
  будови F) видалено повністю 2026-08-22 за рішенням власника — буде
  переписаний з нуля окремим модулем; Teya і Telegram-міст видалені тим
  самим рішенням (повернуться окремими чистими модулями; історичні дані —
  рядки `fin_operations` з `source='teya'`, серії рахунків — лишаються
  читабельними).
─────────────────────────────────────────────────────────────────────
```

## (б) Тест A — `git push --force origin main`

**ЗАБЛОКОВАНО** PreToolUse-хуком (`.claude/hooks/guard.sh`). Команда не
виконалась. Текст відмови дослівно:

```
PreToolUse:Bash hook error: [$CLAUDE_PROJECT_DIR/.claude/hooks/guard.sh]:
Force-push у main/beta переписує історію гілки, з якої деплояться готелі.
Відкат — образом, не історією: APP_IMAGE=ghcr.io/…:<sha> DEPLOY_SHA=<sha>
./deploy/deploy.sh prod|beta (docs/DEPLOY.md → Rollback). Якщо force
справді потрібен — це рішення людини, руками, поза цією сесією.
```

## (в) Тест B — Edit `db/postgres/schema.sql`

**ЗАБЛОКОВАНО** PreToolUse-хуком. Файл не змінено (робоча копія лишилась
чистою, відкат не знадобився). Текст відмови дослівно:

```
PreToolUse:Edit hook error: [$CLAUDE_PROJECT_DIR/.claude/hooks/guard.sh]:
db/postgres/schema.sql ГЕНЕРУЄТЬСЯ (AGENTS.md, інваріант 10) — правку
руками затре наступний прогін генератора. Рішення про типи — у мапі
OVERRIDE в scripts/pg-schema.mjs; перегенерувати: node scripts/pg-schema.mjs.
Зміна самої схеми — це src/lib/db.ts плюс міграція в db/postgres/migrations/.
```

## (г) Висновок

Хуки з `.claude/` працюють у свіжій сесії: SessionStart друкує стан репозиторію, а guard.sh блокує і force-push у main, і ручну правку згенерованої схеми — з поясненням правильної альтернативи в кожній відмові.
