## 2. Обсяг — усе в `docs/research/winhotel/`

1. **`DDL.sql`** — повна схема: `isql-fb -x` (таблиці, колонки, типи, PK/FK, індекси, домени,
   тригери, генератори, view). Як є, без правок.
2. **`TABLES.md`** — таблиця: ім'я → кількість рядків (`SELECT COUNT(*)`) → розмір → наша
   здогадка, що це (з коментарем «упевнено / гіпотеза»). Порожні таблиці — окремим списком.
3. **`MAPPING.md`** — мапа для імпортера, по наших сутностях: **об'єкт і номери** (31 номер,
   поверхи, 7 категорій `DZD DZK SD SK B V ES`; псевдо-номери `9001 SEM`, `9111/9112 APP`,
   `95xx/9999 PS` — як їх відрізнити), **гості** (три адреси, ~40 тис.), **компанії/дебітори**
   (`Debitoren-Nummer` 10000–12599), **брони** (`Beleg-Nr`, `Verkn-Nr` групи, стани
   Reservierung/Angebot/Option/Gastbestätigung, `Buchungs-Segm.`, `Referenz-Nr` Booking,
   `Zimmer FIX`, `Anzahlung`), **послуги на броні** (`Leistungen`: Übernachtung,
   Frühstück-Speisen/Getränke, зірочка = щоденна), **фактури** (`Rechnung-Nr` ~22.4–22.6 тис.,
   рядки з `Gastname`/`Zi-Nr`, оплати в тілі, `Debitor`, `offener Betrag`, ПДВ-рекапітуляція),
   **оплати** (спосіб: bar/Karte/Debitor/…; **де саме лежить TSE-підпис** `Publickey` —
   окремою знахідкою), **ціни** (сезони Neben 01.01–28.02 / Haupt, заселеність 1–4, LOS ≥3,
   Aufbettung 19 €, фірмові −10 %), **політики Storno** («Messe ab 30» і решта),
   **сертифікати/ваучери**, **налаштування ПДВ** (коди 7/19, з якої дати Speisen 7 %).
   Для кожної сутності: таблиця(і) Winhotel, ключові колонки, як зв'язані, що незрозуміло.
4. **`REFERENCE-SAMPLES.md`** — приклади рядків **лише довідників без персональних даних**:
   категорії, номери, послуги, ставки ПДВ, цінові таблиці, політики, джерела броні. По 5–10
   рядків на таблицю. **Жодного рядка з гостей, компаній, броней, фактур, оплат** — навіть
   «знеособленого»: імена, адреси, номери карток, IBAN не потрапляють у git ні в якому вигляді.
5. **`COUNTS-2025-09.md`** — контрольні числа для майбутньої звірки імпорту: гостей, фірм,
   броней (усього / майбутніх на дату знімка / за 2025), фактур (усього / за 2025 / остання
   `Rechnung-Nr`), відкритих дебіторських позицій (сума), непогашених ваучерів (кількість, сума).
   Це числа, не рядки.
6. **`notes.md`** — усе, що здивувало: тригери, що пишуть у кілька таблиць; поля, які виглядають
   як TSE (серійний номер, лічильник підписів, Publickey); кодування тексту (WIN1252/UTF8?);
   дати як текст; що з `WHMXVAKANZ` і `WHMXDOKUMENT`.

## 3. Чого не робити

- Не комітити `.fdb`/`.fbk` і жодних дампів. Після роботи **видалити** базу з контейнера і
  написати в звіті, що видалено.
- Не писати імпортер, не чіпати `src/**`, `hotels/**`, схему, міграції.
- Не «виправляти» дані готелю і не робити висновків про їхню бухгалтерію в документах — лише
  структура і числа. Знахідка про ПДВ-розподіл знижки вже є в `00-JOURNAL.md` §6.2.

## 4. Приймання

`DDL.sql` відновлюється на чистому Firebird 3 без помилок (`isql-fb -i DDL.sql` у порожню
базу — кількість таблиць збігається з `TABLES.md`). У `MAPPING.md` кожна з 11 сутностей §2.3
має названу таблицю або чесне «не знайдено». `git grep -iE "iban|@|strasse|str\." docs/research/winhotel/`
не знаходить персональних даних. Дерево зелене: `npm run check` (гейт `check-no-tenant-names`
має лишитись зеленим — назва готелю в цих документах **дозволена**, це тека `docs/research/`,
але перевір, що гейт так і вважає; якщо ні — назви готель «пілотний готель DE» і напиши в
notes).
