### Правка 2.1 — блокер злиття, схема

SQLite-перебудова `src/lib/db.ts:7073-7111` відходить від домашнього візерунка на найважливішій
таблиці системи. Сусідні перебудови (`db.ts:4496-4545` для `cm_mappings`, `db.ts:5200-5225` для

відтворюють індекси через `IF NOT EXISTS`. У 0094 немає ні транзакції, ні відновлення прагми в
`catch` (`db.ts:7110-7112` — самий `console.error`), ні `IF NOT EXISTS`. Відтворено: залишковий

`[DB] table reservations_new already exists`, далі `[DB] migrations complete`, і `PRAGMA foreign_keys`
після міграцій = **0**. Тобто застосунок обслуговує запити з вимкненою перевіркою зовнішніх ключів
попри `db.ts:61`, і кожен наступний старт повторює те саме, бо міграція вже не завершиться.
Правка — три рядки: `BEGIN`/`COMMIT`, у `catch` `try { ROLLBACK } catch {}` і
`PRAGMA foreign_keys = ON`, індекси через `IF NOT EXISTS`. **Гейт:** `src/lib/db-boot.check.ts` уже
піднімає базу в підпроцесі — два твердження: «після `runMigrations` `foreign_keys` = 1» і «повторний
старт після обірваної перебудови доводить міграцію до кінця». Додатково: `db.ts:7080` — якщо regex
не збігся (`narrow === null`), міграція мовчить, і тиша невідрізненна від «уже полагоджено».
