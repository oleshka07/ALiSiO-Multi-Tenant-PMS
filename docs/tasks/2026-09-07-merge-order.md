# Злиття b4 і b5a в головну — дозвіл і порядок (07.09.2026)

**Від:** контрольна сесія. Перевірка перед злиттям зроблена агентом: правки обох гілок закриті
прогонами, пробне злиття виконано в тимчасовому worktree і повністю прогнано. **Зливати — так.**
Виконує сесія 1.

## Що перевірено на самих гілках

**b4 `2104e485`.** Відновлення після обриву повертає всі 13 індексів, SQL кожного збігається зі
свіжою базою дослівно, включно з предикатом `WHERE unit_id IS NULL`; дублікат гостьового токена
відхиляється (`UNIQUE constraint failed: reservations.guest_page_token`); сцена червона на `2e6b79a`
(`13 → 0`). Класи чипів повернуті, `m-dateChip*`/`m-statusChip*` у дереві немає. `Kč` було у восьми
місцях, усі її переведено; храповик `check-currency-literals` має зуби в обидва боки, базлайн 9 у 4
файлах — справжні випадки в чужих теках.

**b5a `52228fe`.** `unitColumnsSql` спільний для обох списків; живий прогін під роллю `housekeeper`:
`GET /api/units` і `GET /api/properties/[id]` — 200, без `wifi_password`/`lock_code`/`wifi_network`;
власник отримує всі три. Гейт червоніє в обидва боки, зокрема на «звузили занадто». Гейт «голого
node» ловить усі три названі мутації. Каталог — сім мов, 73 рядки, 511 клітин, порожніх нуль;
твердження про повноту червоніє від однієї порожньої клітини; `apply-hotel` на польському готелі дає
`Łazienka`, `Winda`, `Śniadanie`.

## Порядок і як розвʼязувати конфлікти

Послідовність: `work ← b4`, потім `work ← b5a`. Перше злиття дає один конфлікт, друге — **шість**
(`merge-tree` попарно цього не показує).

1. **`package.json`** — обʼєднання наборів. Конфліктує не лише `check`, а й `check:pg`. Підсумок має
   бути: `check` 129 + 140 → 142, потім + 131 → **146**; `check:pg` → **20**. **Після злиття кроки
   перерахувати поіменно, а не дивитись на зелень:** у пробному злитті перша спроба розвʼязати цей
   рядок регексом мовчки викинула девʼять кроків, файл лишився валідним JSON, і `npm run check` був
   зелений. Ланцюжок — один рядок на 30 КБ, втрата гейта в ньому сліду не лишає.
2. **`src/lib/db.ts`** — хвостовий конфлікт, обидві сесії дописували міграції в кінець
   `runMigrations`. Зберегти обидва блоки в порядку номерів: 0090–0094, далі 0110–0111.
3. **`db/postgres/schema.sql`** — **перегенерувати** (`node scripts/pg-schema.mjs`), не брати
   жодну зі сторін: «як у нас» затре таблиці однієї з гілок, і `npm run check` цього не побачить —
   ловить лише postgres-job у CI. Після перегенерації має бути 122 таблиці, у них
   `unit_cleaning_log`, `reservation_files`, `amenity_categories`, `amenities`, `property_amenities`,
   `unit_type_amenities`; `units` з `view/wifi_network/wifi_password/lock_code`; `reservations` з
   CHECK, що містить `'partial'`.
4. **`catalogue.json`, `cs.json`, `de.json`** — обидва набори ключів, 3343 + 3192 → **3392**.
   Розбіжних значень немає жодного.

## Що дав пробний прогін на злитому дереві

`tsc --noEmit` 0; `npm run check` (146 кроків) 0; `check-boundaries --strict` 0 (43 пробої по 16
модулях); `check:i18n` 0 (cs і de 3392/3392); `check:pg` 0; production build 0; `check-isolation`
проти піднятого складання 0, разом із живим прогоном обох маршрутів під покоївкою.
Конкурентних реалізацій після злиття немає: один `useHotelCurrency`, один словник статусів оплати,
одна варта на секрети номера (`unitColumnsSql`), один `latestRate`/`displayRates`. Імена нових гейтів
b4 і b5a не перетинаються. Міграції не конфліктують (0090–0094 і 0110–0111); дубль `0034` уже є на
головній і злиттям не створюється.

## Дрібне, що вливається як є

`src/types/database.ts:264` без `'partial'` (база вже приймає, словник теж; `tsc` мовчить, бо ніхто
через цей тип не присвоює). Кожен старт друкує
`[DB] dead foreign key migration: table "accruals" already exists`.

## Залишки, знайдені понад мої правки — не блокери, у чергу

- **b4:** храповик валюти бачить лише **знаки**, не коди — шість місць зашивають `CZK` у шаблонний
  рядок і лишаються невидимими, зокрема `sites/[siteId]/_components/AnalyticsTab.tsx:75`, той самий
  файл, чий `€` на `:70` стоїть на храповику. Зелений гейт не означає «на екранах немає зашитої
  валюти». Плюс `MobileGuests.tsx:450` — мертвий `const cur = useHotelCurrency()`.
- **b5a:** гейт «голого node» лишає зеленим **динамічний імпорт верхнього рівня в самому скрипті**
  (правило фільтрує лише `own.eagerStatic`) — відтворено: `const late = await import('@properties')`
  першим рядком `provision-org.mjs` не червоніє, хоча падіння те саме. Плюс `units.notes`,
  `created_at`, `updated_at` більше не виходять із `/api/properties/[id]`; єдиний споживач
  (`settings/properties/page.tsx:197`) жодного з них не читає — зміна поведінки без наслідку, але
  назвати варто.
