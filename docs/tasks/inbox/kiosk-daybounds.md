# Знахідка контролера на злитті кіоска — межі доби на SQLite

Не задача блоку, а один дефект, знайдений при злитті `claude/kiosk` 10.09.2026.
Записаний тут, а не полагоджений на злитті, бо це поведінка застосунку, і
неправильний вибір ламає екран доби з іншого боку.

**Що виміряно.** `dayBounds` у `src/apps/kiosk/data/today.repo.ts` віддає межі
доби як `toISOString()` — `2026-09-10T00:00:00.000Z`. Колонка `kiosk_events.at`
на SQLite тримає форму `datetime('now')`, тобто `2026-09-10 14:30:00` — з
ПРОБІЛОМ. Порівняння рядкове, а пробіл (0x20) менший за `T` (0x54):

    Europe/Vienna       from 2026-09-09T22:00:00.000Z   у добі: true
    UTC                 from 2026-09-10T00:00:00.000Z   у добі: false
    America/New_York    from 2026-09-10T04:00:00.000Z   у добі: false

Для Відня проходить ВИПАДКОВО: зсув +2 зносить нижню межу на попередню добу, і
рятує порівняння цифр дня, а не форма. Для будь-якої зони зі зсувом ≤ 0 доба
кіоска на SQLite ПОРОЖНЯ — мовчки, без помилки (AGENTS §7).

**Чого це НЕ стосується.** Беты й проду. Після Д66 `kiosk_events.at` —
`TIMESTAMPTZ` в обох базах Postgres (і в `schema.sql`, і в міграції 0411),
параметр приводить сервер, порівняння правильне. `kiosk.check` зелений і на
SQLite (`npm run check`), і на Postgres (`check:pg`) — саме тому, що фікстура
стоїть у зоні зі зсувом +2. Це фікстура, вироджена на осі ЗОНИ (інваріант 26).

**Що зробити.**

1. Виміряти, у якій формі писати межу, щоб вона була правильна на ОБОХ двигунах.
   Форма коду — `new Date().toISOString().replace('T', ' ').slice(0, 19)`
   (`postgres.ts:81`, і саме її повертає читання TIMESTAMPTZ через
   `SHAPES.timestamp`). Але параметр `YYYY-MM-DD HH:MM:SS` без зони Postgres
   тлумачить у зоні СЕАНСУ — це треба перевірити, а не припустити; якщо зона
   сеансу не UTC, вибір тихо зсуне добу на беті, тобто поламає те, що зараз
   працює.
2. Хай там що обрано — фікстура `kiosk.check` має міряти ЗОНУ: та сама доба в
   зоні зі зсувом ≤ 0 (UTC або `America/New_York`) має давати ті самі числа.
   Без цього наступна правка знову зелена випадково.
3. Якщо рішення виявиться «межі рахує діалект» — це рядок у `docs/DECISIONS.md`
   і, ймовірно, метод у `sql.dialect` поруч із `day()` і `plusMinutes()`.

Знайдено: `check-schema-types --strict` підняв храповик на злитті, далі виміряно
руками. Рішення про тип колонки — Д66.
