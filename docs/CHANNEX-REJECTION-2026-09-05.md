## 3. Що зроблено в коді (Блок 0.5, коміт «Блок 0.5», 05.09.2026)

Кожна зміна — з червоним гейтом до коду (інваріант 24); список гейтів — у
`docs/ARCHITECTURE.md`, таблиця гейтів.

### 3.1 Маска змінених полів у черзі (Б1)

`cm_outbox.field_mask INTEGER` (0066): біти в порядку `RATE_FIELDS` домену —
`prices, closed, minStay, maxStay, noArrival, noDeparture`; NULL = усі (повний
синк, зміна тарифу чи типу, старі рядки). Два рядки однієї координати з
різними масками зливаються тим самим `ON CONFLICT`, що й злиття координат:
побітове АБО, NULL поглинає. Значення далі читаються з джерела в момент
відправлення — маска звужує **тіло**, не джерело (Ц13 цілий).

Писачі: календар (`upsertPrices`, `bulkUpdatePrices`) ставить маску з
**різниці з рядком у базі**, не зі складу запиту — редактор дня шле всю форму
щоразу; матриця й тири — `['prices']`; зміна тарифу, типу, повний синк,
новий мапінг, повернене звіркою — усі поля. Нічого не змінилось — координати
немає взагалі.

`resolveRateNight` віддає лише замасковане; `rateValues` кладе лише те, що є,
тож стиснення діапазонів само порівнює лише замасковані значення: три
сусідні ночі з різним CTA й однаковою ціною під маскою «ціна» — один
`date_range`.

**Ц34 — уточнення И14 (контролер, 05.09).** `stop_sell` їде, коли (а)
змінився стан «закрито» базового рядка, (б) ніч втратила чи здобула джерело
ціни (NULL ↔ число, знятий/повернутий тариф), (в) повний синк. Зміна лише
ціни на відкритій ночі `stop_sell` не несе — вендор тримає свій прапорець, і
«ціна не знімає закриття» (И14) далі істинне. Половину (б) «втратила» тримає
сам батчер — ніч без ціни закривається повз будь-яку маску; половину
«здобула» знає лише писач, і він додає `closed` до маски.

### 3.2 Повний синк несе всі чотири обмеження (Б2)

Без маски ніч без базового рядка отримує **явні** дефолти:
`min_stay_arrival: 1`, `max_stay: 0` («без межі» — так вендор читає й
повертає, `live-fields.json` `GET /restrictions`), `closed_to_arrival:
false`, `closed_to_departure: false`. У дельтах дефолти не вигадуються.
Супутнє: `max_stay` без межі тепер завжди їде нулем, а не мовчить — зняте
обмеження раніше не доїжджало ніколи.

### 3.3 Варта від зайвих пар (Б3)

Пара йде в каталог лише з рядка, де `base_price > 0` — рядок обмежень без
ціни пари не робить (`property-rate-plans.ts`). Зміна ТИПУ (базова ціна,
матриця, місткість) не розсилається на пари **знятих** тарифів: дзеркало їх
памʼятає (Ц25), але координати від типу вони більше не отримують; тариф,
названий явно (зняття з продажу, повернення), — отримує (`outbox-notes.ts`).
Діагностика: `scripts/channex-mappings-live.mjs --org <org> <conn>` (дзеркало
проти `GET /rate_plans`: зайве / відсутнє / розбіжне) і `--remote <id>` — лише
бік вендора, без бази; результат по `505e5d24…` — §2.

### 3.4 Журнал відправлень з тілом

`cm_sends` (0066): кожен виклик — смуга, тіло дослівно, HTTP-статус, task id,
скільки значень, які ключі (`summary`). Невдалий виклик — теж рядок. Екран
Налаштування → Канал-менеджер → «Останні відправлення»: на кожен task id —
смуга, тарифи, дати, **поля в тілі**, статус, кнопка «показати тіло». Це те, що
контролер звіряє з таблицею тесту до подання (CERTIFICATION §7). Ретенція 90
днів кроном GDPR (`/api/cron/gdpr-retention`), по кожній організації в її
контексті.

### 3.5 Підписи полів дат (Б5)

«Виїзд * (ніч виїзду не входить)» у формі броні; «До (остання ніч, входить)»
у масовому редакторі цін; «(виїзд, не входить)» у картці блокування. Форми
блокування з полем дат на десктопі немає — блок ставиться з мобільного
календаря на одну ніч; писачі дат не змінені.
