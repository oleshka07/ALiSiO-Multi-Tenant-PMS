# Hoteliera: як зняти матеріал для дослідження

Обхід машинний. Від людини — один вхід в акаунт і одна команда.

---

## 1. Чому не з цієї сесії

Перевірено 2026-08-29: `curl` із контейнера дістає `403` на CONNECT,
`WebFetch` віддає `EGRESS_BLOCKED`. Мережа середовища до `hoteliera.com`
закрита з обох боків, тож агент не відкриє навіть їхню головну. Обхід
запускається **на вашій машині**, розбір — тут.

`@playwright/test` уже в залежностях проєкту, тож ставити нічого не треба.

## 2. Дві команди

Спершу три умови, кожна з яких інакше валить запуск першим же рядком.

**Тека.** Запускати з кореня репозиторію: `scripts/…` відлічується від
поточної теки, а `@playwright/test` шукається в сусідньому `node_modules`.
З домашньої теки буде `Cannot find module '…\scripts\site-crawl.mjs'`.

**Гілка.** Скрипт живе на `claude/hoteliera-architecture-research-f8or88`.

**Браузер.** Playwright потребує свого; або беремо вже встановлений Chrome.

PowerShell, від початку:

```powershell
cd <тека проєкту>            # там, де лежать package.json і scripts\
git fetch origin
git checkout claude/hoteliera-architecture-research-f8or88
git pull

npm install                  # якщо node_modules ще немає
npx playwright install chromium

# перший раз: відкриється вікно, увійдіть руками, натисніть Enter
node scripts/site-crawl.mjs --start https://app.hoteliera.com/ --login

# далі — сам, скільки б там не було сторінок
node scripts/site-crawl.mjs --start https://app.hoteliera.com/ --max 300
```

Не хочете тягнути окремий браузер — додайте `--channel chrome`, і візьметься
встановлений Google Chrome (він і поводиться як звичайний Chrome, що зайвий
раз не дратує захист від ботів). Chrome стоїть у нетиповому місці —
`--browser "C:\Path\To\chrome.exe"`.

Якщо не пам'ятаєте, де тека проєкту:

```powershell
Get-ChildItem C:\,D:\ -Directory -Recurse -Depth 4 -Filter ALiSiO-Multi-Tenant-PMS `
  -ErrorAction SilentlyContinue | Select-Object -First 5 FullName
```

Профіль браузера окремий (`.crawl-profile`), ваш звичайний Chrome не
чіпається. Логін живе в профілі: наступні запуски входу не потребують.

Окремий профіль — не примха. Chrome від версії 136 не дає під'єднатись
налагоджувачем до основного профілю, тож «взяти вашу поточну сесію» технічно
неможливо; один ручний вхід замінює це повністю.

Вікно відкрите і видиме навмисно: якщо вискочить перевірка «я не робот»,
ви її просто пройдете, і обхід поїде далі.

**Точну адресу кабінету підставте свою** — `app.hoteliera.com` тут здогад.
Скопіюйте з адресного рядка, коли ви в системі. Якщо кабінет розкиданий по
піддоменах, додайте їх: `--host booking.hoteliera.com`.

## 3. Що він знімає з кожного екрана

| Артефакт | Куди | Що з нього видно |
|---|---|---|
| JSON-відповіді | `capture/network.har` | модель даних: ендпоінти, поля, типи, переліки |
| Знімок повної висоти | `capture/shots/*.png` | дизайн, компонування, щільність |
| Опис інтерфейсу | `capture/pages/*.json` | підписи, поля, обов'язковість, підказки, **опції списків**, вкладки, заголовки таблиць, навігація |

Третій рядок — це юзабіліті в машиночитаній формі. Опції списків
найцінніші: саме там лежать їхні статуси, типи тарифів, коди валют, ставки
податків — тобто доменні рішення, а не оформлення.

**Вкладки відкриваються самі.** У SPA вміст невідкритої вкладки не існує ні
в DOM, ні в мережі — без цього половина налаштувань лишилась би невидимою.
Розкривачки (`details`, `aria-expanded`) теж розкриваються.

Далі — схема з мережі:

```bash
node scripts/har-digest.mjs capture/network.har --out digest.json --md digest.md
```

## 4. Рамки, які тримає сам скрипт

- **Читання, не запис.** Клікає лише вкладки й розкривачки. Підписи, схожі на
  «зберегти», «видалити», «надіслати», «оплатити», «створити», **«вийти»** —
  не чіпає ніколи. Вихід у списку не для симетрії: клік по ньому вбив би
  сесію посеред обходу.
- **Форми не надсилає.**
- **За межі свого хоста не ходить** (крім явно доданих `--host`).
- **Пауза між сторінками** — 1200 мс за замовчуванням (`--delay`). Це
  дослідження, а не навантаження.
- **Вміст таблиць не збирається** — лише заголовки колонок і кількість
  рядків. У комірках дані готелю й гостей, вони нам не потрібні.
- **Значення текстових полів не читаються.** Підпис, тип, обов'язковість,
  підказка — так; що саме там написано — ні.

Перевірено запуском на стенді: кнопка «Видалити назавжди» і посилання
«Вийти» не були натиснуті, вкладка «Видалити готель» не відкрита, імена
гостей із таблиці в зібране не потрапили.

## 5. Що все-таки робиться руками (5 хвилин, не 100 сторінок)

**Онбординг.** Ваш акаунт його вже пройшов — майстра налаштування в ньому
більше немає, і краулер його не побачить, бо його там немає. У Hoteliera є
безкоштовний тариф: зареєструйте другий, тестовий акаунт, і запишіть
**лише реєстрацію** — вікном із увімкненим DevTools (F12 → Network →
`Preserve log` → наприкінці «Save all as HAR (with content)»).

Це десяток екранів, не сотня. І це найцінніше з усього списку: значення за
замовчуванням, порядок кроків, що можна пропустити, як виглядають порожні
стани. Прямо закриває нашу Фазу 4 (`docs/ARCHITECTURE.md` §8).

Потім той самий акаунт можна обійти краулером окремо — на порожньому
готелі видно дефолти, яких у налаштованому вже не побачиш:

```bash
node scripts/site-crawl.mjs --start https://app.hoteliera.com/ \
  --profile .crawl-trial --out capture-trial --login
```

**Гостьовий бік Booking Engine.** Публічна сторона бронювання —
без логіна, окремим профілем:

```bash
node scripts/site-crawl.mjs --start <адреса-віджета> \
  --profile .crawl-guest --out capture-guest --max 60
```

## 6. Як передати

Сирий `network.har` і знімки містять cookie сесії, `Authorization` і дані
вашого готелю. **Сире не комітиться**: `.gitignore` закриває `*.har`,
`/capture*/` і `.crawl-profile*`.

Спершу надішліть **мале**:

- `digest.json` — схема API;
- `capture/index.json` — карта розділів;
- `capture/pages/*.json` — описи екранів (це текст, він стискається).

Прочитайте `digest.md` очима перед відправкою: скрипт не знає, що поле
`note` містить прізвище гостя.

Знімки **не надсилайте пачкою** — їх будуть сотні. Я подивлюсь описи
екранів, назву 10–15 конкретних, і ви пришлете саме їх. Дизайн вирішується
на десятку ключових екранів, не на всіх.

## 7. Що з цього буде зроблено

У `docs/research/hoteliera/`:

| Файл | Зміст |
|---|---|
| `DATA-MODEL.md` | їхні сутності й поля, відновлені з дайджесту |
| `SETTINGS-MAP.md` | їхнє дерево налаштувань, поруч наше — і різниця |
| `ONBOARDING.md` | шлях від реєстрації до першої брані, покроково |
| `BOOKING-ENGINE.md` | конфігурація віджета: що налаштовується і як |
| `TAKE.md` | що беремо, що ні, чому — і в якому порядку |

`TAKE.md` — єдиний, який перетворюється на задачі.

Схему БД я не побачу: з відповідей відновлюється **логічна модель** —
сутності, поля, типи, переліки, зв'язки. Для запозичення структури цього
достатньо, але це реконструкція, а не їхній `schema.sql`.

## 8. Межі

Береться **структура**: які сутності, які налаштування, як згруповані, в
якому порядку, які дефолти. Не береться код, тексти й графіка. Наш
інваріант 20 і `check-no-tenant-names` діють і тут: розбір лишається в
`docs/research/`, у код їде наша власна модель.
