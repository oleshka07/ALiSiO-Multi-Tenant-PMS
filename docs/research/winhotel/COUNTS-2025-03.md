Знімок — `WINHOTEL.fbk`, стан на **11.03.2025 08:11** (max `RECHNUNG.DATUM_ZEIT`; max
`BELEGUNG.ERF_DATUM` = 2025-03-11). Не 01.09.2025, як вважалось: `WINHOTEL-TEMP.FDB`
не витягали. Числа потрібні `winhotel-import` для звірки; перед справжнім перенесенням
буде новий знімок і новий файл `COUNTS-<дата>.md` з `aggregates.txt` скрипта.

Усі `COUNT(*)` нижче — **включно з логічно видаленими** (`TA_STATUS >= 1000`): у витягу
лічильники бралися без фільтра. Живі числа дасть крок «агрегати» `extract.sh` (§2).

## 2. Потрібен запит до бази — уже в `extract.sh`, крок «агрегати» → `aggregates.txt`

Кожен рядок — одне число або короткий розподіл «код × N»; персональних даних не
виводить. Таблиці й колонки — з `MAPPING.md`; те, що позначено «гіпотеза», може дати
`ERR` на першому прогоні — тоді поправити SQL, не документ.

| Показник | SQL (Firebird 3) | Примітка |
|---|---|---|
| Остання `Rechnung-Nr` | `SELECT GEN_ID(GEN_RECHNUNGNR, 0) FROM RDB$DATABASE` і `SELECT MAX(RECHNR) FROM RECHNUNG WHERE TA_STATUS < 1000` | генератор — джерело номера; обидва мають збігтись; очікуємо ~22.4–22.6 тис. за екраном, але `RECHNUNG` має 33 тис. рядків — тобто або `RECHNR` не суцільний, або частина — сторно/копії. Звірити |
| Фактур за рік знімка | `… WHERE EXTRACT(YEAR FROM DATUM_ZEIT) = 2025 AND TA_STATUS < 1000` | |
| Броней живих / майбутніх / за рік | `GASTKONT WHERE TA_STATUS < 1000` + `VONAUFH > '2025-03-11'` / `EXTRACT(YEAR FROM VONAUFH) = 2025` | без сміттєвих: дати з `GASTKONT`, не `BELEGUNG` |
| Розподіл станів броней | `SELECT BUCH_STATUS, CI_STATUS, TA_STATUS, COUNT(*) FROM GASTKONT GROUP BY 1,2,3` | дає таблицю станів для `MAPPING.md` п. 4 |
| Адрес живих / з номером дебітора / за типом | `ADRESSEN WHERE TA_STATUS < 1000`; `WHERE DEBI_NR > 0` (+ `MIN`/`MAX` — очікуємо 10000–12599); `GROUP BY ADR_WAHL` | тип адреси розшифрується з `ADR_AUSWAHL` |
| Відкриті дебіторські позиції: кількість і сума | `EXECUTE BLOCK` над `GET_OFFEN_ZAHLBETRAG(LNR)` для `GASTKONT` з `CI_STATUS = 2` (виїхали) і `offen <> 0`; плюс `SELECT DB_STATUS, COUNT(*), SUM(UMSATZ)/1000 FROM AUSGBUCH GROUP BY 1` | перший — як рахує сам Winhotel (послуги − платежі по рахунку); другий — книга вихідних рахунків, значення `DB_STATUS` розшифрувати на прогоні (гіпотеза: 0 = не сплачено) |
| Депозити на живих бронях | `SELECT COUNT(*), SUM(ANZA_BETRAG)/1000 FROM GASTKONT WHERE TA_STATUS < 1000 AND ANZA_BETRAG > 0` | |
| Непогашені ваучери: кількість, сума | продано: `BUCHKONT WHERE LEIST_LNR IN (7, 55, 95) AND TA_STATUS < 1000` (N, `SUM(GBETRAG)/1000`); погашено: `ZAHLUNGEN JOIN DEVISEN … WHERE BEZEICHN LIKE '%GUTSCHEIN%'`; різниця — сальдо | реєстру немає (`GUTSCHEINE` 0), тому лише сума, без номерів ваучерів; кількість непогашених з бази не виводиться |
| Сума живих рядків рахунків / платежів | `SUM(GBETRAG)/1000`, `SUM(BETRAG)/1000` | контроль загальної суми імпорту |
| TSE: підписано / не підписано | `SELECT SIGN_OK, COUNT(*) FROM FISKAL_BK GROUP BY 1` | скільки рядків без підпису |

Усі суми в базі — `BIGINT` ×1000; у `aggregates.txt` вони вже поділені на 1000.
