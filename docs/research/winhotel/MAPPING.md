# Winhotel.MX → ALiSiO: мапа таблиць для `winhotel-import`

Стан 09.09.2026, сесія 5. **Головна база не отримана** (`notes.md` §1), тому в колонці
«Таблиця Winhotel» усюди чесне «не знайдено». Заповнена натомість колонка «що шукати»:
вона складена з того, що видно на екранах Winhotel (журнал контрольної сесії §2, §5,
§6, переказано в задачі `docs/tasks/2026-09-09-winhotel-schema.md` §0 і §2.3) і з
конвенцій вендора, знятих з єдиної отриманої бази (`TABLES.md`): PK `LNR`, посилання
`LNR_<ціль>`, скорочення `GK` = гість, `ADR` = адреса, `RECHNR` = номер фактури,
FK-констрейнтів немає. Після `extract.sh` кожен рядок закривається за 10–20 хвилин:
`keyword-hits.txt` уже відфільтрує колонки за цими ж словами.

Позначки впевненості: **упевнено** — таблиця названа і колонки прочитані;
**гіпотеза** — здогадка з екранів; **не знайдено** — бази не було.

## 1. Об'єкт і номери → `properties`, `unit_types`, `units`

| | |
|---|---|
| Таблиця Winhotel | **не знайдено** |
| Що шукати | таблиця з ~31+ рядками і колонкою номера (`ZIMMER`, `ZI_NR`, `ZINR`), поверх (`ETAGE`, `STOCK`), категорія (`KAT`, `ZIKAT`, `ZIMMERKAT`); окремий довідник категорій із 7 кодами `DZD DZK SD SK B V ES` |

| Псевдо-номери | `9001 SEM` (семінар), `9111/9112 APP` (апартаменти), `95xx/9999 PS` (паркомісця?) — відрізняти за номером ≥ 9000 **і** за категорією; імпортер має вирішити, що з них стає `units`, що `event_spaces`, що не імпортується взагалі — рішення не цієї сесії |

## Загальне для імпортера (з отриманої бази — упевнено)

- **FK немає** — цілісність посилань не гарантована; імпорт має рахувати «сироти»
  (рядок броні без гостя, фактура без адреси) і звітувати, а не падати.
- **`LNR` можна задавати ззовні** (тригер ставить `GEN_ID` лише при NULL) — тобто в
  історичних даних можуть бути «ручні» id поза послідовністю генератора.
- **charset NONE** — декодувати як WIN1252 і перевірити на умлаутах (ä, ö, ü, ß);
  один неправильно декодований символ у прізвищі — це неправильний Meldeschein.
- **Тип id не сталий** (`BIGINT` проти `INTEGER` для того самого `LNR_GK`) — у мапі
  типів імпортера не покладатись на DDL однієї таблиці.
