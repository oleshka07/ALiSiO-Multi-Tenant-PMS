## 1. Що було

Вісім екранів читали «який обʼєкт», і кожен тримав власний стан:

```ts
const [propertyId, setPropertyId] = useState('');
if (arr[0]) setPropertyId(arr[0].id);      // ← щоразу перший
{properties.length > 1 && ( <select …> )}   // ← селектор лише коли готелів 2+
```

З одним готелем це непомітно. З двома кожен екран незалежно скидався на
ПЕРШИЙ — оператор не «постійно вибирав», він щоразу починав із чужого
готелю. Ціни з цих екранів їдуть у менеджер каналів і на Booking, тож
правка не того обʼєкта — тиха втрата грошей, рівно той клас, який тут
ловлять усюди (AGENTS інваріант 29: межа проходить по даних, не по екрану).

Гейт на нинішньому коді (03.09.2026, до перенесення) — 11 місць у 8 файлах:

| Файл | Що |

## 2. Що зроблено

**Один провайдер.** `src/ui/PropertyScopeContext.tsx` — `PropertyScopeProvider`
у розкладці `app/(dashboard)/layout.tsx`, один на обидві гілки (десктоп і
мобільна). Екран читає `usePropertyScope()`: `properties`, `propertyId`
(`null` — «Усі обʼєкти»), `property`, `setPropertyId`, `refresh`.

**Один елемент у шапці.** `components/layout/PropertySwitcher.tsx` — у
`Header` (десктоп) і `MobileHeader` (телефон), праворуч, як у Channex.
Назва поточного обʼєкта видна завжди: з одним обʼєктом — статичний підпис,
з двома й більше — перемикач із пунктом «Усі обʼєкти».

**Адреса + кука.** Порядок старшинства:

1. `?property=<id>` або `?property=all` в адресі вкладки — головна. Дві
   вкладки на два готелі не бʼються між собою; посилання з областю можна
   переслати колезі. Провайдер сам дописує параметр після переходу бічним
   меню (`history.replaceState`, без перезавантаження), тож адреса вкладки
   завжди називає її область.
2. Кука `property_scope` (httpOnly, рік) — ПАМʼЯТАЄ останній вибір, читається
   лише коли в адресі нічого немає (нова вкладка). `POST /api/auth/property`
   (`withActor`; чужий id — 404), `/api/auth/me` віддає `properties` і
   `property`.
3. Інакше «Усі обʼєкти». Ніколи не «перший».

Чужий або видалений id в адресі чи куці — не вибір (інваріант 13).
Це презентація, не безпека: орендар лишається на сесії й зʼєднанні, політики
бази обʼєкта не знають, API-маршрути далі приймають `property_id` явно.

**Екрани налаштувань вимагають рівно один обʼєкт.** `<PropertyRequired>`
(`components/layout/PropertyRequired.tsx`): за «Усі обʼєкти» показує картку
«Оберіть обʼєкт» із кнопками, за нуль обʼєктів — «Спершу заведіть обʼєкт».
Обгорнуто: тарифи, ціни за заселеністю, майстер каналів, гостьова сторінка,
номерний фонд, обʼєкти (крім кнопки «Додати»), загальні (блок обʼєкта).

**Списки звужуються за обʼєктом і показують колонку «Обʼєкт» за «Усі».**
Броні (десктоп і телефон; `property_id` у `/api/bookings`), дашборд
(заїзди, виїзди, завантаженість; `/api/dashboard?property_id`), звіти
(`/api/reports?property_id`; оплати — через бронь, бо `fin_operations` не
має обʼєкта). Чужий id у параметрі дає порожньо — організація стоїть у
кожному WHERE і без нього, це не друга перевірка власності. Екран «Ціни»
звужує типи номерів до обраного обʼєкта; за «Усі» показує всі. Нова
задача отримує обʼєкт області. Форма броні бере ставку турзбору ОБРАНОГО
обʼєкта (за «Усі» — порожньо, портьє вводить сам); картка броні — обʼєкта
самої броні, без запасного першого.

**Стани екрана.** `components/ui/State.tsx` — порожньо (з реченням і
кнопкою), завантаження, помилка, відмова; токени й правила — в
docs/UI-LANGUAGE.md. У Блоці 1 стоять на тарифах, цінах за заселеністю,
номерах, обʼєктах, бронях і дашборді; решта — Блок 4.

**Гейт.** `check-property-scope.mjs --strict` у `npm run check`. Червоним:
власний стан області (`useState` під іменем `propertyId`, `selectedProperty`,
`currentProperty`…), «перший обʼєкт як вибір» (`properties[0]`, `props[0]`,
`propData[0]`), читання `?property` або куки повз провайдер. Коментарі
вирізаються; самоперевірка на зразках перед кожним скануванням — правило,
що не червоніє на зразку, зупиняє гейт з кодом 2 (інваріант 24).

## 3. Що свідомо не зроблено

- **Календар, гості, фінанси не звужуються за обʼєктом.** Календар
  переїжджає в Блоці 3 — з описом того, що в ньому є зараз; гості —
  організаційна книга; фінанси не мають обʼєкта в рядках операцій.
- **`/app/p/<id>/…` не заводиться.** Обидва варіанти з NEXT-TASKS
  дозволені; `?property=` не чіпає дерево з 77 маршрутів і жодного
  `href` у меню. Дорожчий варіант не дає нічого, чого не дає дешевший.
- **Копіювання між обʼєктами** («взяти тариф із одного готелю в інший») —
  окремий діалог, не перемикач області. Не в цій задачі.
